SCR-016 設定

バッチ・Gmail・AI・提案テンプレートの各種設定

画面（連携済み） 画面（Gmail未設定）
画面ID: SCR-016URL: /settings

1. 画面概要

システム全体の動作パラメータを管理する。取込パイプライン後のルール採点・AI 判定対象の上位人数、メール振り分けラベル・検索ワード、提案メール送信、連携中の Gmail アカウント、送信元アドレスなどを確認・設定する。

2. 設定項目

バッチ / AI採点

設定キーUI説明
ai_assist_enabledトグルルールスコア採点完了時に、上位候補へ AI 補助評価・理由生成を自動実行。OFF の場合は画面から手動実行
ai_judgement_top_n数値 1–20ai_assist_enabled が ON の場合だけ表示・適用。案件ごとに AI 判定へ渡す上位人数（既定 5）
ingest_times時刻入力（複数）+ 保存 + 追加1日の取込実行時刻（HH:MM）を複数登録。例: 08:00, 12:00。「取込時間を追加」で入力欄を増やす
ingest_data_retention_days数値 0–3650この日数より古い取込データを削除する。0 は自動削除無効。BAT-006 が参照

Gmail / AI

gmail_connected_account連携中 Gmail アカウント（読み取り専用）
gmail_auth_status連携状態・最終確認日時（読み取り専用）
gmail_sort_source_label振り分け対象の Gmail ラベル（例: SES未振り分け）
gmail_sort_label_talent振り分け後の要員ラベル（例: SES人材紹介）
gmail_sort_label_project振り分け後の案件ラベル（例: SES案件配信）
gmail_sort_keywords_talent要員判定用検索ワード（改行区切り）
gmail_sort_keywords_project案件判定用検索ワード（改行区切り）
gmail_sort_unknown_label判別不能時に付与する Gmail ラベル（例: SES要確認）
apply_from_address応募・提案メールの送信元
outreach_template_project_propose案件提案用テンプレート（人材紹介メールへ案件を送る）。プレースホルダ: recipient_name, items
outreach_template_talent_propose人材提案用テンプレート（案件メールへ要員を送る）。プレースホルダ: project_title, items

AI モデルは環境変数（例: OPENAI_MODEL / バッチ設定）で指定し、設定画面の system_settings には持たない。

スキルマスタ

取込時に自動追加されるスキルとカテゴリを管理する。カテゴリはアコーディオンで開閉し、配下スキルのカテゴリ変更・カテゴリ追加/削除・名前変更・並び順変更（↑↓）が可能。人材一覧・案件一覧のスキル検索選択肢に反映する（GET /api/skills/catalog・カテゴリ更新は PATCH /api/skills/categories/{id}）。

3. 処理仕様

  • 保存 → PUT /api/settings で system_settings を一括更新
  • 連携中 Gmail アカウントは Gmail API の profile 情報または token.json の認証結果から表示し、画面保存対象には含めない
  • 再連携 → Gmail OAuth 認可フローを起動し、成功後に token.json を更新する（設定画面から Client ID/Secret 入力可）
  • gmail_sort_* 設定は BAT-001 メール振り分けバッチの次回実行から適用する
  • 振り分けバッチは gmail_sort_source_label 付きメールを対象とし、件名を優先して gmail_sort_keywords_talent / gmail_sort_keywords_project と照合する。件名だけで判定できない場合のみ本文先頭（既定 500 文字）も参照する
  • 要員キーワードのみヒット → gmail_sort_label_talent、案件キーワードのみヒット → gmail_sort_label_project を付与する
  • 件名・本文を合わせても両方に該当する、またはどちらにも該当しない場合は gmail_sort_unknown_label（判別不可）を付与する
  • ingest_data_retention_days は BAT-006 過去データ削除バッチの次回実行から適用する。0 の場合は削除処理をスキップする
  • 取込パイプラインの実行順は BAT-001 → BAT-002 → BAT-006 → BAT-003 →（ai_assist_enabled なら BAT-004）→ BAT-008 とする
  • パイプラインではメール取込完了後に全案件×要員をルールベースで採点する（ルールスコアによる足切りは行わない）
  • ai_judgement_top_n は人材詳細・案件詳細の「AI採点」押下時、およびパイプライン内の AI 採点に適用。NG はスコア 0
  • ルール採点の手動実行入口は SCR-004 案件一覧（旧 SCR-010 は廃止）
  • 同一案件×同一要員の AI 判定結果がキャッシュ済みの場合は再利用し、AI API 呼び出しを行わない
